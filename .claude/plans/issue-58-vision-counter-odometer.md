## 概要と方針

現状のカウンターは `app/vision/page.tsx` 内にインラインで `{count.toLocaleString()}人が宣言しました` と表示している。
これを、**起動時から `00000` のゼロ埋め表示**で始まり、宣言が届くたびに**機械式オドメーター風に数字がロール**して増える表示に作り直す。
ロール演出を持つためGSAPを使い、メモリリーク対策（Tween破棄）を伴うので、**専用コンポーネント `Counter` に切り出す**。

### 表示仕様
- 桁数：最大 10,000（5桁）に合わせ**5桁ゼロ埋め**（例：`00042人`）。桁数は定数化する。
- カウント対象：従来どおり `isVisible=true` の件数（`page.tsx` の `count`。ロジックは変えない）。
- ロール：数字が**上から下へずれる**オドメーター風。新しい（大きい）数字が上から入り、古い数字が下へ抜ける向き。
  桁ごとに独立したリール（0〜9の帯）を持ち、**変化した桁だけ**ロールさせる。桁上がり（9→0）は
  リールを順方向に回し切ってから瞬間リセットし、**逆回転に見えないよう自然な桁上がり**にする。
- サイズ：#56 の `--screen-scale` 方式に合わせ、余白・文字サイズを画面追従させる。

### レイアウト（暫定・実装時にプレビューで調整）
- 「宣言数」ラベル ＋ `00000人` の数字（オドメーター）を、**豪華めの枠**（発光ボーダー＋半透明の暗い背景の
  ガラス風パネル）で囲む。既存のサイバー／発光トーン（白＋水色グロー）に合わせる。
- ラベル文言・枠デザインは未確定。初期案を出し、`?count=` などのプレビューまたは実データで見た目を確定する。

## 実装ステップ

1. `lib/constants.ts` に定数を追加する。
   - `COUNTER_DIGITS = 5`（最大10,000＝5桁のゼロ埋め）
   - `COUNTER_ROLL_MS`（1桁がロールしきる時間）／`COUNTER_ROLL_STAGGER_MS`（下位→上位など桁ごとのずらし。任意）
   - マジックナンバーを避け、Counter からこれらを参照する。
2. `components/vision/Counter.tsx` を新規作成する。
   - props：`value: number`。`String(value).padStart(COUNTER_DIGITS, '0')` で5桁の文字列にする。
   - 各桁を「0〜9を縦に並べたリール」で描画し、`overflow:hidden` の窓で1桁だけ見せる。
   - `value` 変更を監視する effect（初回はアニメーションせず即セット）で、**変化した桁のリールだけ**
     GSAP で目標桁までロールさせる。桁上がりは順方向に回し切ってから瞬間リセット（逆回転を防ぐ）。
   - GSAP Tween は次回ロール前・アンマウント時に `kill()`（多重・リーク防止）。ref に現在の桁状態を保持。
   - 数字の右に「人」、上または左に「宣言数」ラベルを置く。枠（発光パネル）で囲む。
   - `prefers-reduced-motion` 時はロールせず即座に目標桁へ切り替える。
3. `components/vision/Counter.module.scss` を新規作成する。
   - 枠（ガラス風パネル：`backdrop`/半透明背景＋発光ボーダー）、桁リールの窓（固定高さ・overflow hidden）、
     等幅数字（`font-variant-numeric: tabular-nums` または固定幅セル）でゼロ埋めの桁が崩れないようにする。
   - 余白・サイズは `calc(... * var(--screen-scale, 1))`（#56）。既存 `.counter` の白文字＋濃い縁取り影を踏襲。
4. `app/vision/page.tsx` を改修する。
   - `import Counter from '@/components/vision/Counter'`。
   - `<div className={styles.counter}>...</div>` を `<Counter value={count} />` に差し替える。
   - count 算出ロジック（onValue の isVisible カウント）は変更しない。
5. `app/vision/page.module.scss` から旧 `.counter` ルールを撤去する（位置指定は Counter 側 or ラッパーで担保）。
6. `npm run build` / `npx tsc --noEmit` / `npm run lint` を通す。プレビューで見た目（枠・ロール向き・桁上がり）を確認・微調整。

## 考慮が必要な点

### メモリリーク対策（8時間以上稼働）
- ロールの GSAP Tween は、次のロール開始前と**アンマウント時に必ず `kill()`**。`useRef` で Tween 配列 or
  桁ごとの Tween を保持し、cleanup で破棄する。DOM要素はReact管理なので手動生成しない（animations.ts と違い宣言的に描く）。
- `value` の高頻度更新（連続宣言）でも、進行中Tweenを kill→再ロールで破綻しないようにする。

### 型
- `any` 禁止。props は `{ value: number }`。桁状態の ref は `number[]`（各桁の現在値）で型明示。

### 表示の正確性
- ゼロ埋めは `padStart(COUNTER_DIGITS, '0')`。10,000到達時に5桁（`10000`）が収まること。
  万一 `value` が 99,999 を超える運用（想定外）でも桁あふれで崩れないよう、桁数は文字列長で動的にクランプ or
  最低 COUNTER_DIGITS を保証する（基本は5桁固定で十分）。
- カウント自体は `isVisible=true` 件数（既存ロジック）と一致。表示層のみの変更。

### ロール向き・桁上がり（要確認）
- 「上→下」の向き、桁上がりの順回転リセットは実装後にプレビューで確定。向きは定数/フラグで切替可能にしておく。

### スコープ外（今回はやらない）
- 宣言吸収（#44）の完了と厳密に同期してカウントを増やす因果制御は本Issueの完了条件に含まれないため対象外。
  `value`（count）変更に反応して即ロールする方式とする（必要なら別Issueで因果同期を検討）。
