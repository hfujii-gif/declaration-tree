# レビューエージェント ルール

このファイルはコードレビューを担当するClaude Codeエージェントが従うルールを定義します。
レビューを始める前に必ずこのファイルとプロジェクトルートの `CLAUDE.md` を読んでください。

---

## レビューの基本方針

レビューの目的は「バグを見つけること」だけでなく、
「仕様通りに実装されているか」「本番当日に安全に動くか」を確認することです。
このシステムはイベント当日に止まれないため、
特にFirebase接続・エラーハンドリング・メモリリークを重点的に確認してください。

---

## レビュー手順

### 1. PRを受け取ったら最初にやること
```bash
# 対象ブランチをチェックアウトして確認する
gh pr checkout {PR番号}

# 変更ファイルの一覧を確認する
git diff develop --name-only

# ビルドが通るか確認する
npm run build
npx tsc --noEmit
npm run lint
```

### 2. CLAUDE.mdの仕様と照合する
対象Issueの仕様をCLAUDE.mdで確認し、実装が仕様通りかチェックする。

## レビューチェックリスト

### 【必須】仕様との整合性
- [ ] CLAUDE.mdに記載された仕様通りに実装されているか
- [ ] Issueの「完了条件」チェックリストがすべて満たされているか
- [ ] 文字数制限がMAX_CHARS（50）を使っているか（マジックナンバーではないか）
- [ ] タイムアウトがRESET_DELAY_MS（3000）を使っているか
- [ ] マイルストーンがMILESTONES配列を使っているか

### 【必須】TypeScript
- [ ] `any` 型が使われていないか
- [ ] `types/index.ts` で定義した型（Declaration・DeclareRequestBody等）を正しく使っているか
- [ ] 関数の引数・返り値に型が明示されているか
- [ ] `npx tsc --noEmit` でエラーがないか

### 【必須】Firebase操作
- [ ] Firebase操作が `lib/firebase.ts` からimportされているか（直接initializeしていないか）
- [ ] `onValue()` のリスナーがuseEffectの返り値で必ず解除されているか
```typescript
// ✅ 正しい解除の書き方
useEffect(() => {
  const declarationsRef = ref(db, 'declarations')
  const unsubscribe = onValue(declarationsRef, (snapshot) => {
    // 処理
  })
  return () => unsubscribe()  // ← これがないとメモリリーク
}, [])
```
- [ ] Firebase書き込みにtry-catchが実装されているか

### 【必須】エラーハンドリング
- [ ] すべてのFirebase操作にtry-catchが実装されているか
- [ ] API Routeがエラー時に適切なステータスコード（400・405・500）を返しているか
- [ ] フロントエンドがAPIエラー時にユーザーへ通知しているか
- [ ] エラー時にテキストがリセットされないこと（再入力できる状態を維持）

### 【必須】セキュリティ
- [ ] `.env.local` の内容がコードにハードコードされていないか
- [ ] `process.env.NEXT_PUBLIC_*` 以外の環境変数がフロントエンドに露出していないか
- [ ] `/api/declare` がPOST以外のメソッドで405を返しているか

### 【重要】/input 入力画面固有のチェック
- [ ] キーボードが送信後のオーバーレイ表示中も閉じないこと（画面遷移していないこと）
- [ ] 送信完了後にtextareaRef.current?.focus()が呼ばれているか
- [ ] NGワードバリデーションが入力中にリアルタイムで動作しているか
- [ ] 空文字・空白のみで送信ボタンが押せない状態になっているか

### 【重要】/vision ビジョン画面固有のチェック
- [ ] isVisible=falseの宣言がカウントに含まれていないか
- [ ] カウンターがisVisible=trueの宣言のみをカウントしているか
- [ ] 新着宣言（`onChildAdded()`）でパーティクル吸収演出（中央表示→マトリックス分解→木へ吸収→発光）が再生されるか
- [ ] 旧・葉システム（宣言ごとのテキスト葉追加・`LeafItem` 等）が撤去され、葉前提の配線が残っていないか
- [ ] 木の成長が3段階（小/中/大）で、`GROWTH_THRESHOLDS` / `GROWTH_TREE_SCALE` / `GROWTH_HUE` を使っているか（マジックナンバーでないか）
- [ ] 満開フィナーレが10,000到達時のみで、発光が一時的（演出後に定着しない）実装になっているか。中間マイルストーン（2,500/5,000/7,500）の達成演出が残っていないか
- [ ] 満開・成長段階の判定が二重発動しない仕組みになっているか（prevCountRefなど）
- [ ] 長時間稼働を想定したメモリリーク対策（Firebaseリスナー解除・GSAP/パーティクルの破棄）が実装されているか

### 【重要】/admin 管理画面固有のチェック
- [ ] パスワード認証が実装されているか
- [ ] 宣言の削除が物理削除ではなく `isVisible: false` への更新になっているか
- [ ] NGワードの変更がFirebaseに保存されているか（ローカルstateだけで終わっていないか）

### 【確認】コード品質
- [ ] 不要な `console.log` が残っていないか
- [ ] コメントが日本語で適切に書かれているか（複雑な処理に説明があるか）
- [ ] SCSS ModulesでCSS変数（var(--color-bg)等）が使われているか
- [ ] マジックナンバー（50・3000・10000等）が直接書かれていないか

## レビュー結果の報告方法

### レビューの投稿方法（毎回必須）

レビュー結果は会話への出力だけで終わらせず、**毎回必ず対象のPRにコメントとして投稿する**こと。
さらに、コードの修正・改善提案が特定の行に紐づく場合は、**該当箇所のコードに対してインラインコメントを付ける**こと
（サマリーだけにまとめず、指摘した行に直接コメントを残す）。

```bash
# サマリー（総評）＋ 行ごとのインラインコメントを1つのレビューとしてまとめて投稿する。
# event は COMMENT（自分が作成したPRは APPROVE できないため）。
# comments[].line は新ファイル側の行番号。
gh api repos/{owner}/{repo}/pulls/{PR番号}/reviews --method POST --input review.json

# review.json の例
# {
#   "event": "COMMENT",
#   "body": "## レビュー結果：✅ 承認 ...（総評）",
#   "comments": [
#     { "path": "lib/ngWords.ts", "line": 7,  "body": "ここは readonly にすると安全です（任意）" },
#     { "path": "app/vision/page.tsx", "line": 42, "body": "onValue のリスナー解除が漏れています（必須）" }
#   ]
# }
```

- **必須修正**・**任意修正**のどちらも、行に紐づくものはインラインコメントにし、本文（body）には総評と必須/任意の一覧を書く。
- インラインコメントには `必須`／`任意（非ブロッキング）` を明記し、対応の要否がひと目で分かるようにする。
- 単純なサマリーコメントだけが必要な場合は `gh pr comment {PR番号} --body "..."` でもよいが、**行に紐づく指摘がある場合は必ず上記のインラインコメント方式を使う**。

### 問題なしの場合
```
## レビュー結果：✅ 承認

### 確認内容
- 仕様との整合性：OK
- TypeScript型：OK
- Firebase操作・メモリリーク対策：OK
- エラーハンドリング：OK
- セキュリティ：OK

### コメント
（気になった点があれば任意で記載）

LGTM 🎉
```

### 問題ありの場合
```
## レビュー結果：❌ 修正依頼

### 必須修正（マージ前に対応が必要）
1. **[Firebase] onValue()のリスナーが解除されていない**
   - ファイル：app/vision/page.tsx
   - 問題：useEffectの返り値でoff()が呼ばれていないためメモリリークが発生する
   - 修正方法：
     ```typescript
     return () => off(declarationsRef)
     ```

### 任意修正（対応推奨だがマージはOK）
1. **[品質] console.logが残っている**
   - ファイル：app/input/page.tsx 23行目
   - 本番では不要なのでできれば削除してください
```

## レビュー時に特に注意するポイント

### イベント当日に止まれないシステムなので特に重視する項目
1. **Firebaseリスナーの解除** → メモリリークで長時間後にクラッシュする
2. **エラーハンドリング** → Firebaseエラーが握りつぶされると無音で止まる
3. **満開フィナーレの二重発動** → 10,000到達演出が複数回発動すると見た目が壊れる
4. **環境変数の露出** → 本番の認証情報が漏れる

### レビューしなくていいこと
- デザインの細かい好み（色・余白など）
- コメントの文言の細かい表現
- 実装方法の好み（仕様を満たしていれば方法は問わない）
