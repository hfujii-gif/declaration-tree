# テストエージェント ルール

このファイルはテストを担当するClaude Codeエージェントが従うルールを定義します。
テストを始める前に必ずこのファイルとプロジェクトルートの `CLAUDE.md` を読んでください。

---

## テストの基本方針

このシステムはイベント当日に止まれないため、
「動けばいい」ではなく「本番当日8時間以上安定して動く」を基準にテストしてください。
バグを発見したら修正はせず、必ずIssueを作成して報告してください。

---

npm run dev

### /api/declare

```bash
# テスト用コマンド（ローカルサーバー起動中に実行）
BASE_URL="http://localhost:3000"

# ✅ 正常系：通常の宣言
curl -s -X POST $BASE_URL/api/declare \
  -H 'Content-Type: application/json' \
  -d '{"text": "毎日運動する"}' | jq
# 期待：{"success": true} + HTTP 200

# ❌ 異常系：空文字
curl -s -X POST $BASE_URL/api/declare \
  -H 'Content-Type: application/json' \
  -d '{"text": ""}' | jq
# 期待：{"success": false, "message": "宣言を入力してください"} + HTTP 400

# ❌ 異常系：空白のみ
curl -s -X POST $BASE_URL/api/declare \
  -H 'Content-Type: application/json' \
  -d '{"text": "   "}' | jq
# 期待：{"success": false} + HTTP 400

# ❌ 異常系：51文字（50文字を超える）
curl -s -X POST $BASE_URL/api/declare \
  -H 'Content-Type: application/json' \
  -d '{"text": "あいうえおかきくけこさしすせそたちつてとなにぬねのはひふへほまみむめもやゆよらりるれろわをんあ"}' | jq
# 期待：{"success": false, "message": "50文字以内で入力してください"} + HTTP 400

# ❌ 異常系：GETリクエスト
curl -s -X GET $BASE_URL/api/declare | jq
# 期待：{"message": "Method Not Allowed"} + HTTP 405

# ❌ 異常系：DELETEリクエスト
curl -s -X DELETE $BASE_URL/api/declare | jq
# 期待：HTTP 405
```

#### マイルストーン演出のテスト
```bash
# Firebaseコンソールから直接データを追加して宣言数を増やす
# または以下のスクリプトでテストデータを一括投入する

# 2500件のテストデータを投入（本番前に削除すること）
for i in $(seq 1 2500); do
  curl -s -X POST http://localhost:3000/api/declare \
    -H 'Content-Type: application/json' \
    -d "{\"text\": \"テスト宣言 $i\"}" > /dev/null
done
```

| マイルストーン | 期待する演出 |
|---|---|
| 2,500人達成 | 木が拡大→縮小・「2,500人達成！」テキスト表示 |
| 5,000人達成 | 木が拡大→縮小・「5,000人達成！」テキスト表示 |
| 7,500人達成 | 木が拡大→縮小・「7,500人達成！」テキスト表示 |
| 10,000人達成 | 花びら散布・光エフェクト・「1万人達成！」テキスト表示 |
| 二重発動しないこと | 同じマイルストーンで演出が2回発動しない |

## バグ報告の手順

バグを発見した場合は修正せず、必ず新しいIssueを作成すること。

```bash
# バグIssueの作成
gh issue create \
  --title "[Bug] バグの内容を簡潔に記載" \
  --label "bug" \
  --body "## 発生環境
- ブラウザ：Chrome / Safari
- 画面：/input / /vision / /admin / /api/declare

## 再現手順
1. 〇〇をする
2. 〇〇をする
3. バグが発生する

## 期待する動作
〇〇が表示されるはずだった

## 実際の動作
〇〇が表示された（またはエラーが発生した）

## エラーメッセージ（あれば）
\`\`\`
エラーメッセージをここに貼る
\`\`\`

## 関連するIssue
#（元のIssue番号）"
```
