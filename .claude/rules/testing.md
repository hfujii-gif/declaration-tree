# テストエージェント ルール

このファイルはテストを担当するClaude Codeエージェントが従うルールを定義します。
テストを始める前に必ずこのファイルとプロジェクトルートの `CLAUDE.md` を読んでください。

---

## テストの基本方針

このシステムはイベント当日に止まれないため、
「動けばいい」ではなく「本番当日8時間以上安定して動く」を基準にテストしてください。
バグを発見したら修正はせず、必ずIssueを作成して報告してください。

---

### /api/declare

```bash
# テスト用コマンド（ローカルサーバー起動中に実行）
BASE_URL="http://localhost:3000"

# ✅ 正常系：通常の宣言
curl -s -X POST $BASE_URL/api/declare \
  -H 'Content-Type: application/json' \
  -d '{"text": "毎日運動する"}' | jq
# 期待：{"success": true} + HTTP 200

# ❌ 異常系：空文字
curl -s -X POST $BASE_URL/api/declare \
  -H 'Content-Type: application/json' \
  -d '{"text": ""}' | jq
# 期待：{"success": false, "message": "宣言を入力してください"} + HTTP 400

# ❌ 異常系：空白のみ
curl -s -X POST $BASE_URL/api/declare \
  -H 'Content-Type: application/json' \
  -d '{"text": "   "}' | jq
# 期待：{"success": false} + HTTP 400

# ❌ 異常系：51文字（50文字を超える）
curl -s -X POST $BASE_URL/api/declare \
  -H 'Content-Type: application/json' \
  -d '{"text": "あいうえおかきくけこさしすせそたちつてとなにぬねのはひふへほまみむめもやゆよらりるれろわをんあいうえお"}' | jq
# 期待：{"success": false, "message": "50文字以内で入力してください"} + HTTP 400

# ❌ 異常系：GETリクエスト
curl -s -X GET $BASE_URL/api/declare | jq
# 期待：{"message": "Method Not Allowed"} + HTTP 405

# ❌ 異常系：DELETEリクエスト
curl -s -X DELETE $BASE_URL/api/declare | jq
# 期待：HTTP 405
```

### /vision ビジョン画面

| No. | テスト内容 | 操作 | 期待する結果 |
|---|---|---|---|
| 1 | リアルタイム反映 | /inputから宣言を送信する | 1秒以内に宣言到着の演出が始まる（中央にテキストが表示される） |
| 2 | パーティクル吸収演出 | 宣言を送信して観察する | 中央に画面の約1/3サイズでテキスト表示→1文字ずつマトリックス風に分解→中央の木へ吸い込まれる→木が発光する、が順に再生される |
| 3 | 演出の直列再生 | 複数の宣言を短時間に連続送信する | 中央スポットライトは同時に1つだけ。宣言演出が1件ずつ順番に再生され、重なって破綻しない |
| 4 | カウンター更新 | 宣言を送信する | カウンター（00000ゼロ埋め・機械式ロール表示）が1増える |
| 5 | 非表示の宣言 | 管理画面で宣言を非表示にする | カウンターが即座に1減る（葉は廃止済みのため画面から消える葉はない） |
| 6 | カウンターの正確性 | 非表示の宣言があるときにカウンターを確認する | isVisible=trueの件数だけカウントされている |
| 7 | 複数の同時送信 | 複数台から同時に送信する | すべての宣言の演出が取りこぼしなく反映される（キューに積まれ順に再生される） |

#### テストデータの一括投入
```bash
# Firebaseコンソールから直接データを追加して宣言数を増やす
# または以下のスクリプトでテストデータを一括投入する（件数は目的に応じて変更）

# N件のテストデータを投入（本番前に必ず削除すること／Issue #30）
for i in $(seq 1 600); do
  curl -s -X POST http://localhost:3000/api/declare \
    -H 'Content-Type: application/json' \
    -d "{\"text\": \"テスト宣言 $i\"}" > /dev/null
done
```

> **しきい値の一時変更について**：木の成長段階（小/中/大）や満開フィナーレを、大量投入せずローカルで確認したい場合は、`lib/constants.ts` の `GROWTH_THRESHOLDS`（小→中→大の境界）や、満開判定の到達数を一時的に小さくして検証する。**確認後は必ず本来の値（`GROWTH_THRESHOLDS = [500, 1000]` / `MILESTONES = [10000]`）に戻してからコミットすること。**

#### 木の成長段階のテスト（#57）
累計 isVisible=true 件数に応じて、中央の木が **小 / 中 / 大** の3段階に変化する（旧・マイルストーンごとの scale 拡大は廃止）。

| 段階 | 累計件数 | 期待する見た目 |
|---|---|---|
| 小 | 0〜500 | 幹・木全体が最も小さい。葉の色は緑のみ |
| 中 | 501〜1,000 | 木が中サイズ。樹冠のモリモリ（膨らみ・突起の量）が増える。葉の色に一部レインボーが混ざる |
| 大 | 1,001〜 | 木・幹が最大。樹冠が最も膨らむ。葉が全色相（虹）になる |
| 段階の切替演出 | しきい値通過時 | 段階が上がる瞬間、発光で木を覆って差し替わる（急にパッと入れ替わらない） |
| 大の維持 | 10,000到達後 | 「大」のまま維持される（それ以上大きくならない・後退しない） |
| 文字密度 | 全段階 | 葉の文字密度は段階で変わらない（常時「大」相当） |

#### 満開フィナーレ（10,000人達成）のテスト
中間マイルストーン（2,500 / 5,000 / 7,500）の達成演出は**廃止**。達成演出は10,000到達時の満開フィナーレのみ。

| テスト内容 | 期待する演出 |
|---|---|
| 10,000人達成 | 光が画面全体に広がる満開フィナーレが再生される |
| 発光の一時性 | フィナーレの発光は一時的。演出後は通常の「大」の木に戻る（発光が定着し続けない＝旧 `data-bloomed` の常時発光は復活しない） |
| 中間マイルストーン非発動 | 2,500 / 5,000 / 7,500 では達成演出が一切発生しないこと |
| 二重発動しないこと | 10,000到達で満開演出が2回発動しない（`prevCountRef` 等で担保） |

### /admin 管理画面

| No. | テスト内容 | 操作 | 期待する結果 |
|---|---|---|---|
| 1 | 正しいパスワードでログイン | 正しいパスワードを入力してログイン | 管理画面が表示される |
| 2 | 間違ったパスワードでログイン | 間違ったパスワードを入力してログイン | インラインのエラーメッセージ（「パスワードが違います」）が表示されてログインできない |

| 5 | 宣言の再表示 | 非表示にした宣言を再表示する | /visionに再度表示される |
| 6 | NGワードの追加 | 新しいNGワードを追加する | /inputでそのワードを入力するとエラーが出る |
| 7 | NGワードの削除 | 登録済みNGワードを削除する | /inputでそのワードを入力してもエラーが出なくなる |

## バグ報告の手順

バグを発見した場合は修正せず、必ず新しいIssueを作成すること。

```bash
# バグIssueの作成
gh issue create \
  --title "[Bug] バグの内容を簡潔に記載" \
  --label "bug" \
  --body "## 発生環境
- ブラウザ：Chrome / Safari
- 画面：/input / /vision / /admin / /api/declare

## 再現手順
1. 〇〇をする
2. 〇〇をする
3. バグが発生する

## 期待する動作
〇〇が表示されるはずだった

## 実際の動作
〇〇が表示された（またはエラーが発生した）

## エラーメッセージ（あれば）
\`\`\`
エラーメッセージをここに貼る
\`\`\`

## 関連するIssue
#（元のIssue番号）"
```
